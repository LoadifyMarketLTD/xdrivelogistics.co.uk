# XDrive Driver — Production Android Signing

Production package: `co.uk.xdrivelogistics.driver`

## Current state

The repository contains **no verified production keystore or certificate lineage**. No new key is generated by the repository. Release builds are intentionally fail-closed until the existing Play signing/upload-key state is verified.

Google Play requires an update to keep the same package name, use a greater versionCode and use the accepted signing/upload lineage. If Play App Signing is enabled, Google holds the app-signing key while XDrive supplies the registered upload key.

## Required evidence before first production bundle

In Google Play Console for `co.uk.xdrivelogistics.driver`, record:

1. Whether the package already exists.
2. Highest versionCode already uploaded, if any.
3. Whether Play App Signing is enabled.
4. App-signing certificate SHA-256 fingerprint.
5. Upload certificate SHA-256 fingerprint.
6. Whether an existing upload keystore is available to XDrive.

Do not commit private keys, passwords or service-account material to Git.

## If the existing upload keystore is recovered

Compare its certificate fingerprint with the Upload key certificate shown in Play Console. Only after it matches, provide these secrets to Gradle through environment variables or protected local Gradle properties:

- `XDRIVE_ANDROID_KEYSTORE_PATH`
- `XDRIVE_ANDROID_STORE_PASSWORD`
- `XDRIVE_ANDROID_KEY_ALIAS`
- `XDRIVE_ANDROID_KEY_PASSWORD`

Then a release bundle may be built and its certificate verified before upload.

## If the upload key is lost

Do not create a replacement and immediately upload it. Use the official Google Play **Request upload key reset** process first, then register the replacement certificate in Play Console. The app-signing key held by Play is a different key and must not be replaced casually.

## Build policy

- Debug builds do not require production signing secrets.
- Release/bundle tasks fail before build when the signing values above are absent.
- No debug signing fallback is allowed for production.
- Expo Preview signing is unrelated to production Native Android signing and must never be reused as assumed production lineage.
